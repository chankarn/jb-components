# 06 · ตรวจก่อนส่งงาน

ทำทุกข้อก่อนบอกผู้ใช้ว่า "เสร็จแล้ว" · ข้อไหนทำไม่ได้ (เช่น ไม่มีเบราว์เซอร์) ให้บอกผู้ใช้ตรงๆ ว่าข้ามข้อไหน

## 1. คำสั่ง

```bash
npm run typecheck
```

```bash
npm test
```

```bash
npm run build
```

แก้ props/JSDoc ของคอมโพเนนต์ในคลัง → `npm run docs:api` · แก้คู่มือ → `npm run docs:check`

## 2. ตรง requirement

- [ ] ทุกข้อในตาราง requirement (ขั้นที่ 1 ของ [01-workflow](./01-workflow.md)) มีหน้าจอ/การทำงานรองรับ
- [ ] ใช้คอมโพเนนต์ในคลังทุกที่ที่มี (ไม่มี `<input type="date">`, `<select>`, `window.confirm`, modal/dropdown ทำเอง — ดู "ห้ามทำเอง" ใน [03](./03-requirement-map.md#ห้ามทำเอง-มีในคลังแล้ว--เขียนใหม่--พังซ้ำ))
- [ ] ส่วนที่สร้างใหม่ แจ้งผู้ใช้แล้วว่าคืออะไร และควรย้ายเข้าคลังไหม

## 3. สถานะครบทุกแบบ (หน้าที่มีข้อมูล)

- [ ] กำลังโหลดครั้งแรก (skeleton) · โหลดซ้ำ (`LoadingOverlay`) · ไม่มีข้อมูล (`EmptyState` + ปุ่มเพิ่ม) · ค้นไม่เจอ (`EmptyState` + ล้างตัวกรอง) · ผิดพลาด (`toast.error` + ลองใหม่)
- [ ] ฟอร์ม: ช่องว่าง/รูปแบบผิดแสดงใต้ช่อง · กดบันทึกซ้ำไม่ได้ระหว่างส่ง · สำเร็จแจ้งผล · มีการแก้ไขค้างแล้วออก → ถามก่อน
- [ ] ลบ/ทิ้ง → `confirmDialog` ก่อน

## 4. ตรวจในเบราว์เซอร์

- [ ] **จอ 375px**: ไม่มี scroll แนวนอน · ข้อความไม่ล้น/ไม่ทับ · ปุ่มกดง่าย
- [ ] **จอกว้าง 1280px+**: เนื้อหาไม่ยืดจนอ่านยาก (`max-w-*`)
- [ ] **โหมดมืด**: สลับแล้วไม่มีพื้นขาว/ตัวหนังสือมองไม่เห็น (ถ้ามี = ใส่สีตรงแทน token)
- [ ] **คีย์บอร์ด**: Tab ไปได้ทุกปุ่ม/ช่องตามลำดับ · เห็นกรอบโฟกัส · Esc ปิดหน้าต่าง · Enter ส่งฟอร์ม
- [ ] **ปุ่มลัด**: แสดง ⌘ บน Mac / Ctrl บน Windows (ทดสอบด้วยการจำลองมือถือ Android = แสดงแบบ Windows)
- [ ] **console**: ไม่มี error/warning (โดยเฉพาะ hydration mismatch, key ซ้ำ, label ซ้อน)
- [ ] รีเฟรชหน้ารายการแล้วตัวกรองยังอยู่ (เก็บใน URL)

## 5. คุณภาพโค้ด

- [ ] ไม่มีสี hex / `text-gray-*` / `bg-white` / `dark:` (ยกเว้นสีแบรนด์ภายนอก)
- [ ] ไม่มี opacity ที่ไม่มีในสเกล (`/12`, `/7` …)
- [ ] `Field as="div"` ทุกช่องที่ไม่ใช่ input เดี่ยว
- [ ] ไม่มี `Math.random()`/`Date.now()` ตอน render
- [ ] ปุ่มไอคอนมี `aria-label` · รูปมี `alt`
- [ ] ข้อความภาษาไทยสุภาพ สั้น ข้อความผิดบอกวิธีแก้
- [ ] ตรรกะที่ซับซ้อน (ตรวจฟอร์ม คำนวณเงิน กรองข้อมูล) แยกเป็น `.ts` และมี test

## 6. รายงานผู้ใช้

บอกสั้นๆ: ทำอะไรไป (หน้า/คอมโพเนนต์) · ตรวจอะไรแล้วผ่าน · ข้ามอะไรเพราะอะไร · สิ่งที่ต้องทำต่อ (ต่อ API จริง, ตั้งสีแบรนด์ ฯลฯ)
