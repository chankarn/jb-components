# 01 · ขั้นตอนทำงานเมื่อได้ requirement มา

ทำตามลำดับนี้ทุกครั้ง อย่าข้ามไปเขียนโค้ดทันที

## ขั้นที่ 1 — แตก requirement เป็นรายการ "หน้า" และ "สิ่งที่ผู้ใช้ทำ"

อ่าน requirement ทั้งหมดก่อน แล้วเขียนออกมาเป็นตาราง:

| หน้า / ส่วน | ผู้ใช้ทำอะไร | ข้อมูลที่แสดง/กรอก |
|---|---|---|
| เข้าสู่ระบบ | กรอกอีเมล+รหัส · จดจำ · ลืมรหัส | อีเมล, รหัสผ่าน |
| รายการสินค้า | ค้นหา · กรองสถานะ/หมวด · เรียง · แบ่งหน้า · ลบ | ชื่อ รหัส ราคา สต็อก สถานะ |
| … | … | … |

## ขั้นที่ 2 — จับคู่แต่ละข้อกับคอมโพเนนต์

เปิด [03-requirement-map.md](./03-requirement-map.md) แล้วหาคำที่ตรงกับ requirement (เช่น "เลือกหลายอัน + ค้นหา" → `Combobox multiple`)
ถ้าเป็นทั้งหน้า ดูสูตรใน [04-page-recipes.md](./04-page-recipes.md) ก่อน — มักมีครบแล้ว

**สร้าง "แผนคอมโพเนนต์" ก่อนลงมือ** (ส่งให้ผู้ใช้ดูได้):

```text
แผนคอมโพเนนต์ — <ชื่องาน>

โครงทั้งเว็บ
- AppShell (sidebar: ภาพรวม, สินค้า, คำสั่งซื้อ · topbar: ⌘K, การแจ้งเตือน, เมนูผู้ใช้)
- CommandPalette + useCommandHotkey
- FeedbackHost (toast/confirm) — อยู่ใน root layout แล้ว

หน้า /products (สูตร: รายการ)
- AdminPageHeader (breadcrumb + ปุ่มเพิ่ม)
- Tabs สถานะ (มีตัวเลข) · Toolbar (ค้นหา) + FilterSelect หมวด
- DataTable + RowMenu (แก้ไข/ลบ) · Pagination
- confirmDialog ก่อนลบ → toast พร้อม action "เลิกทำ"
- EmptyState เมื่อไม่พบ

หน้า /products/new (สูตร: ฟอร์ม)
- SectionCard ×3 · Field + Input / Combobox / NumberInput / TagInput / DatePicker / FileDrop
- RadioGroup variant="card" (สถานะ) · Switch
- LoadingButton ในแถบบันทึกติดล่าง · useShortcut('s')

ที่คลังไม่มี (ต้องทำเพิ่ม)
- ปฏิทินจองคิวรายชั่วโมง → สร้างใหม่ใน src/components/ ตามกฎใน 05-rules.md
```

## ขั้นที่ 3 — เช็กว่าคลังขาดอะไร

ถ้า requirement ไม่ตรงกับอะไรในคลังเลย:
1. ดูว่า **ประกอบจากของที่มี** ได้ไหม (เช่น "การ์ดสินค้าแบบกดเลือกได้" = `RadioGroup variant="card"`, "ขั้นตอนสมัคร" = `Stepper`)
2. ถ้าไม่ได้จริง ค่อยสร้างใหม่ โดยใช้ของกลางที่มีอยู่ข้างใน: `Popover`/`useFloating` (อะไรที่ลอย), `Dialog`/`Drawer`/`useModal` (หน้าต่าง), `Field` (ห่อช่องกรอก), `shake()` (ตอบสนองตอนผิด), token สี (ห้ามใส่สีตรงๆ) — ดู [05-rules.md](./05-rules.md)
3. แจ้งผู้ใช้ว่าส่วนไหนสร้างใหม่ และควรย้ายกลับเข้าคลังกลางไหม

## ขั้นที่ 4 — ลงมือ

- ก๊อปจากสูตร/ตัวอย่างที่ใกล้ที่สุดแล้วปรับ อย่าเริ่มจากศูนย์ (ตัวอย่างใน `src/app/demo/**` และ `src/app/Gallery.tsx` รันได้จริงทั้งหมด)
- ดู props ที่แน่นอนใน [docs/api](../api/README.md) — **อย่าเดา prop** (เช่น `DatePicker` ใช้ค่าเป็นสตริง `YYYY-MM-DD` ไม่ใช่ `Date`)
- ข้อความบนหน้าจอเป็นภาษาไทยที่สุภาพและสั้น · ข้อความผิดพลาดบอกวิธีแก้ (เช่น "รหัสนี้มีสินค้าอื่นใช้แล้ว" ไม่ใช่ "invalid")
